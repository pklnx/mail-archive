# Web UI
- Carbon progress bars carry no `helperText`: it adds an untranslatable "Loading".
- Class names in views are Carbon's (`cds--`) or defined in `web/src/layout.css`, generic helpers prefixed `app-`; `web/src/layout.test.ts:88` enforces it.
- pnpm is 12.9.1 (`packageManager` in `web/package.json`); corepack is broken in cloud sessions. Call the cached `pnpm.mjs` through a wrapper in your own shim directory; check its path exists first.
- Carbon's packages and IBM Plex run a telemetry script after install that reports to IBM. `web/pnpm-workspace.yaml` blocks the install scripts of all of them, and the install fails on a new dependency with a script not listed there: list it, never allow it. `IBM_TELEMETRY_DISABLED=true` stays set in the `Makefile`, CI and the `Dockerfile`.
- Fonts are bundled (`web/src/fonts.css`). Carbon's CSS loads them from IBM's CDN, so `web/build/stripRemoteFonts.ts` writes a copy without those rules to `web/src/vendor/carbon.css` when Vite starts, and `pnpm build` fails if the dist refers to another host (`web/scripts/check-dist.mjs`). Carbon's built-in English texts get German ones in the `carbon` section of `web/src/i18n.ts`.
- The mail view is the initial bundle; every other view loads on demand (#288): `App.tsx` loads Accounts, Users, Retention, Log, Profile and the keyboard shortcuts overview with `lazyNamed()` from `web/src/lazyView.tsx`, each in a `LazyView` (a skeleton while the chunk loads; a notice with a Retry button that reloads the page when it does not, e.g. after an upgrade). The forced password and 2FA screens in `Auth.tsx` take their forms from the Profile chunk. A new view gets `lazyNamed()` and an entry in `web/scripts/lazyChunks.mjs`, shared by `check-dist` and `web/e2e/lazy.spec.ts`.
- `check-dist` measures the initial JS (the entry script of `index.html` and every chunk it imports statically, `web/scripts/initialBundle.mjs`), prints it raw and gzip on every build (`check-dist: initial JS … bytes`) and fails over 579 000 bytes (the #282 number), on a lazy chunk missing or in the initial bundle, or when the computed chunks differ from the `modulepreload` links. The budget is raised only in a PR that says why.
- Every loading state is a Carbon skeleton in `Loading` from `lazyView.tsx` (tables: `TableSkeleton` from `tableSkeleton.tsx`); its status says "Loading…" to screen readers only, one status per screen, so a second part loading at the same time passes `announce={false}`. Visible "Loading…" text is not allowed (`web/src/loadingGuard.test.ts`).
- The app's own motion is written only inside `@media (prefers-reduced-motion: no-preference)` in `layout.css`, with Carbon's motion tokens as `--app-duration-*` / `--app-easing-*` (`web/src/motion.test.ts`).
- Colours come from the pklnx design system ([pklnx/design-system](https://github.com/pklnx/design-system), #211): Carbon v11 unchanged, with Purple instead of Blue as the interactive colour (buttons, links, focus in light mode, interactive borders). `web/src/index.css` imports its generated theme, `@pklnx/design-system/theme/pklnx-carbon.css`, right after Carbon's CSS and in the same `carbon` layer; its rules use the theme classes `theme.ts` sets on `<html>` (`cds--white`, `cds--g100`) with Carbon's specificity and replace Carbon's token values, so light and dark mode need nothing else, and the file has no URLs, so `check-dist` is unaffected. No colour value is copied into this repository.
- The design system package is a tarball attached to its GitHub release: `web/package.json` names the release asset's URL and `web/pnpm-lock.yaml` pins its integrity; it needs no registry account, has no install script, and pnpm's one-day release age does not apply to it (bumps: `docs/development/index.md`, "Dependencies").
- Design system rules: at most one `kind="primary"` button per view (a tab panel and a modal each count as one view; Carbon's `Button` is primary without a `kind`), the others `secondary`, `tertiary` or `ghost`; never `support-caution-undefined`, which is Purple in Carbon and would look like the interactive colour.
